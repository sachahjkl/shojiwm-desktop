Documentation

Overview

shojiwm-desktop is a complete desktop for the ShojiWM Wayland compositor. It has three parts:

The compositor configuration (src/, TypeScript)
ShojiWM runs it from ~/.config/shojiwm. It draws the window frames and manages the windows: placement, Aero Snap, Alt+Tab, Aero Peek, screen zoom, window groups and the keys.
The shell shojiwm-shell (crates/shell/, Rust)
It draws everything that is not a window frame: the taskbar, the Start menu, the launcher, the notification area, the desktop, the dialogs, the Control Panel, the lock screen and the log-on screen. It is built on AntiWebUI, a GPU-rendered native UI toolkit by bea4dev, the author of ShojiWM.
The portal (portal/, Rust, optional)
An xdg-desktop-portal GlobalShortcuts backend, so that programs can bind global keys.

No file from Windows is copied, embedded or required. The artwork is original, except the colour icons, which are built from KDE's Oxygen icons (LGPL-3.0-or-later).

Requirements

  • ShojiWM from the integration branch of sachahjkl/ShojiWM, installed and registered as a session. The branch carries what upstream does not have yet: the ext-data-control-v1 global (clipboard history) and labels' textShadow (the caption titles).
  • A GPU driver with Vulkan or OpenGL. AntiWebUI renders with wgpu.
  • Fonts: Inter, else Noto Sans. The Kernel theme also uses JetBrainsMono Nerd Font (JetBrainsMono NF) for its titles and clock.
  • An icon theme with an application-x-executable icon, such as Adwaita or Papirus.
  • fd, for the files that the Start menu and the launcher find.
  • dconf and a settings portal that reads it (xdg-desktop-portal-gtk), for light and dark in programs. On NixOS, set programs.dconf.enable = true.
  • PAM: the lock screen checks the password with the login service (/etc/pam.d/login).
  • The default programs: kitty (terminal), Thunar (file manager), Chromium (browser) and inspecteur (task manager). Control Panel › Default Programs, or the session environment, chooses others.

Optional: NetworkManager for the network panel, BlueZ for the Bluetooth panel, PipeWire with wpctl for the volume, playerctl for the media keys, Hokum for notifications, systemd for the power actions and the Action Center.

Install

The flake github:sachahjkl/shojiwm-desktop provides:

OutputWhat it is

packages.<system>.shellThe shell, bin/shojiwm-shell.
packages.<system>.portalThe GlobalShortcuts portal, xdg-desktop-portal-shojiwm-desktop.

NixOS

Add the flake as an input of your system flake:

{
  inputs.shojiwm-desktop = {
    url = "github:sachahjkl/shojiwm-desktop";
    inputs.nixpkgs.follows = "nixpkgs";
  };
}

Then, in a NixOS module that receives inputs:

{ inputs, pkgs, ... }: let
  desktop = inputs.shojiwm-desktop.packages.${pkgs.stdenv.hostPlatform.system};
in {
  imports = [ inputs.shojiwm-desktop.nixosModules.greeter ];

  # The shell: the compositor configuration starts `shojiwm-shell`.
  environment.systemPackages = [ desktop.shell desktop.icon-theme pkgs.kdePackages.oxygen-icons pkgs.fd ];
  programs.dconf.enable = true;

  # Global shortcuts for programs such as OBS or Discord.
  xdg.portal = {
    extraPortals = [ desktop.portal ];
    config.shojiwm."org.freedesktop.impl.portal.GlobalShortcuts" = "shojiwm-desktop";
  };

  # The log-on screen. Turn off the display manager you had.
  services.displayManager.ly.enable = false;
  services.shojiwm-desktop-greeter = {
    enable = true;
    user = "alice";
    defaultSession = "shojiwm-uwsm";
    mainScreen = "HDMI-A-1";
    monitors = [
      { output = "HDMI-A-1"; mode = "3840x2160@60"; position = "0x0"; scale = 1.875; }
    ];
  };
}

Link the directories of desktop.default into ~/.config/shojiwm with the tool that manages your home files, or run the install app once (next section). Do not touch ~/.config/shojiwm/node_modules: ShojiWM manages it.

The log-on screen section lists every option of the module.

Nix, without NixOS

  1. Install the shell into your profile: 
    nix profile install github:sachahjkl/shojiwm-desktop#shell
  2. Install the configuration into ~/.config/shojiwm: 
    nix run github:sachahjkl/shojiwm-desktop#install

    The command replaces src, assets and shell, and copies package.json and tsconfig.json. It does not touch node_modules or settings.json.

  3. Log out and start the ShojiWM session, or press Super+Shift+R in a running one.

Without Nix

  1. Build the shell. It links fontconfig, freetype, libxkbcommon, wayland, PAM and libxcb, and loads Vulkan or OpenGL, Wayland and PipeWire at run time. 
    git clone https://github.com/sachahjkl/shojiwm-desktop.git
cd shojiwm-desktop/crates/shell
cargo build --release
install -Dm755 target/release/shojiwm-shell ~/.local/bin/shojiwm-shell
  2. Copy the configuration: 
    cd ../..
mkdir -p ~/.config/shojiwm
rm -rf ~/.config/shojiwm/src ~/.config/shojiwm/assets ~/.config/shojiwm/shell
cp -R src assets shell package.json tsconfig.json ~/.config/shojiwm/
  3. Make sure that ~/.local/bin is in the session's PATH, then start the ShojiWM session.

First run

  1. If ~/.config/shojiwm/node_modules/shoji_wm does not exist, run ShojiWM's init-config first. It creates that link.
  2. Log on to the ShojiWM session. The configuration starts shojiwm-shell once per session.
  3. The shell writes ~/.config/shojiwm/settings.json with the defaults if the file does not exist.
  4. Tap Super to open the Start menu. Open Control Panel there to choose the theme, the background and the programs.
  5. If the screens are wrong, open Control Panel › Screen Resolution, or set SHOJIWM_DESKTOP_OUTPUTS.

The compositor writes its log to ~/.local/state/shoji_wm/logs/latest.log. After a change to src, press Super+Shift+R to reload the configuration.

Chromium and Firefox draw their own title bar by default. To give Chromium the theme's frame, right click its tab strip and turn on Use system title bar and borders. Firefox has the same setting under Customise toolbar › Title bar.

Themes

Choose the theme in Control Panel › Appearance and Personalization › Light, dark and glass. The shell and the window frames change at once. The choice is the theme key of settings.json: "aero" or "kernel".

Aero

  • Windows 7's glass. The frame, the caption buttons and the title were measured pixel by pixel from Windows 7 screenshots; docs/aero-measurements.md lists every number and its source.
  • The compositor blurs what is behind the captions, the taskbar and the menus (Light, dark and glass: Clear to Frosted, glassBlur 0 to 4).
  • A glass colour from a palette of fifteen, at an intensity you set (glassColor, glassColorStrength).
  • Rounded corners of 8 px, or square corners (squareCorners), which also squares the menus, buttons and fields.
  • The taskbar is at the bottom of the screen, with the round orb.

Kernel

  • A deep blue-black desk under a dotted grid.
  • Steel-blue caption plates with a line of light and darkened edges, a dark outline, a red close button and vector caption icons. Titles in JetBrains Mono.
  • A thin bar at the top of the screen, with a launcher plate instead of the orb, flat buttons and a monospaced clock. The bar's menus, the Start menu, the Run dialog, the desktop icons and the gadgets follow it to the top.
  • Section titles in monospaced spaced capitals after an accent bar. Each Control Panel category has its own colour.

Light and dark

Both themes have a light and a dark version. The choice is the system's preference: dconf's org.gnome.desktop.interface color-scheme, which the settings portal passes to GTK, libadwaita, Qt, Firefox and Chromium. The same page changes it, or:

shojiwm-shell msg appearance setDark true
shojiwm-shell msg appearance toggle

With the built-in background, the desktop and the lock screen show a night version of it in dark.

Window groups

A group is several windows in one frame, as tabs. The frame of the shown window draws one tab for each window of the group.

  1. Drag a window by its caption over the caption of another window. The dragged window turns see-through, and a ghost tab shows where it will go.
  2. Release the pointer. The dragged window becomes a tab of the other window's frame.
  • Click a tab to show its window.
  • Drag a tab along the strip to move it. Drag it out of the strip to take its window out of the group.
  • The × of a tab closes its window.
  • Super+Ctrl+Left and Right show the previous and the next tab. Super+Ctrl+Down takes the shown tab out of the group.
  • The taskbar still lists every window. If you choose a hidden tab there, the group shows it.

Ghostty asks for the theme's frame. Its new-tab key (Ctrl+Shift+T, set to open a new window) opens a tab in the group of the window where you pressed it. TABBED_PROGRAMS in src/groups.ts lists such programs.

The shell

shojiwm-shell runs once per session. The compositor configuration starts it. With the argument greeter, it is the log-on screen. With msg, it sends a command to the running shell.

Surfaces

Taskbar
The orb (Aero) or the launcher plate (Kernel), the program buttons, the notification area, the clock and the show-desktop strip. Every window of one program sits behind one button (combineWindows). Buttons show the icon alone by default (taskbarCompact). Pinned programs keep their button while closed. A middle click, Ctrl+click or Shift+click starts another instance. Progress, counts and urgency come from the com.canonical.Unity.LauncherEntry signal. Auto-hide slides the bar away to a 2 px line.
Thumbnails and jump lists
Rest on a button to see its windows as cards; a click raises one, a middle click closes it. A media player's cards have previous, play or pause, and next (MPRIS). A right click opens the jump list: recent files (from recently-used.xbel), pinned files, the tasks of the program's .desktop file, a new instance, and close.
Start menu
Pinned programs, the programs you start most, and All Programs in folders by category. On the right: your full name, your folders, Recent Items, Control Panel, Run, and the power button with its menu. Type to search programs, Control Panel tasks and files. Return with nothing found runs what you typed.
Launcher
The Start menu's search alone, on the focused screen (Super+Shift+D). Before you type, it lists the programs you started last (launcherRecentCount, 25 by default). The search is fuzzy: the typed letters must come in order in a name, so fx finds Firefox. Letters side by side, at the start of a word or of the name, rank higher; the matched letters are highlighted. Drag its sides to resize it.
Run dialog
The Open field with the last 26 commands and completion from them. A folder, a file or an address opens with xdg-open; anything else runs in a shell.
Notification area
Tray items with their menus, and hidden icons behind the arrow. The shell's own icons: volume, network, Bluetooth, notifications (the bell), the Action Center (the flag) and the clock. Each opens a panel on a click and a menu on a right click. The clock opens a calendar; Date and Time adds up to two more time zones.
Desktop
The background (picture or slide show), the desktop icons, the desktop menu, sticky notes, the CPU meter and clock gadgets, and the Mystify screen saver.
Dialogs
Shut Down Windows, the orb's menu, and the Alt+Tab titles (the compositor draws the panel, the shell its text).
Control Panel
A window with its own taskbar button. Pages: Light, dark and glass (with the theme choice), Desktop Background, Screen Resolution, Lock Screen, Account Picture, Taskbar and Start Menu, Notification Area Icons, Date and Time, Ease of Access, Devices and Printers, Sound, Default Programs, Startup Programs, System.
Lock screen
The clock, your account picture, your name and the password field, on the main screen; the other screens stay black. PAM checks the password. Super+L, the Start menu, loginctl lock-session, sleep (lockOnSuspend) and inactivity (lockAfterMinutes) lock it.

Commands

The compositor's keys drive the shell with commands. You can send the same commands from a terminal or a script:

shojiwm-shell msg <target> <function> [arguments]

The shell listens on $XDG_RUNTIME_DIR/shojiwm-shell.$WAYLAND_DISPLAY.sock. It prints the answer, if any. If the call fails, it prints the error and exits with status 1. A screen argument is a connector name such as DP-2; an empty one means the main screen.

Examples:

shojiwm-shell msg controlpanel openPage display
shojiwm-shell msg taskbar activate 3
shojiwm-shell msg lock lock

Other files

  • Notifications: Hokum draws them. assets/hokum/aero.kdl is a Windows 7 balloon theme for it. In ~/.config/hokum/config.kdl, set theme "~/.config/shojiwm/assets/hokum/aero.kdl" and behaviour { position "bottom-right" }. The bell of the notification area keeps the notifications in ~/.local/state/shojiwm-desktop/notifications.json.
  • Sticky notes: ~/.local/state/shojiwm-desktop/notes.json.
  • Frame sizes and colours: src/themes/<theme>/metrics.ts.
  • Shell sizes and colours: crates/shell/src/theme_values.rs.
  • Programs that open as tabs: TABBED_PROGRAMS in src/groups.ts.

Log-on screen

shojiwm-shell greeter is the lock screen as a log-on screen for greetd: the picture, the clock, the account picture and the password field on the main screen, black on the others, and the session to start in the bottom-left corner. If PAM asks a second question after the password, such as a one-time code, the field asks it. The log-on screen keeps the last session chosen.

NixOS module

nixosModules.greeter enables greetd, starts a Hyprland of its own with your screens, and runs the log-on screen in it. When a session starts, that Hyprland exits and greetd runs the session. If the log-on screen exits without starting a session (a crash, or Ctrl+Alt+Delete), greetd shows its text log-on (agreety), which starts the default session.

Global shortcuts

Programs such as OBS or Discord bind their keys through the GlobalShortcuts portal, which ShojiWM does not have. packages.<system>.portal provides it. It takes each program's preferred keys and asks the compositor configuration to bind them. It sends the program Activated when the keys go down and Deactivated when any of them goes up, so hold-to-talk works. There is no dialog to choose other keys: change them in the program.

On NixOS, see the xdg.portal lines in the install example. The name in config.shojiwm is the desktop name in lowercase: xdg-desktop-portal reads shojiwm-portals.conf.

Architecture

ShojiWM + src/

Frames, window manager, Snap, Alt+Tab panel, Peek, zoom, window groups, keys. Listens on $SHOJIWM_DESKTOP_SOCKET.

shojiwm-shell

Taskbar, menus, panels, desktop, Control Panel, lock screen. Listens on shojiwm-shell.$WAYLAND_DISPLAY.sock.

portal

GlobalShortcuts over D-Bus for programs; connects to $SHOJIWM_DESKTOP_SOCKET.

Keys → shojiwm-shell msg … → shell. Shell → $SHOJIWM_DESKTOP_SOCKET → compositor: Peek, show desktop, screens, theme, glass, corners, animations, programs. Compositor → shell: the Alt+Tab titles.
The compositor configuration
ShojiWM runs src/index.tsx. It starts shojiwm-shell once per session and gives it SHOJIWM_DESKTOP_SOCKET: ShojiWM's own socket path with -desktop.sock at the end. src/peek.tsx serves that socket with ShojiWM's protocol: one JSON object per line, { "method", "params" }, and { "id", "method", "params" } for a request.
From the compositor to the shell
A key such as Super runs shojiwm-shell msg startmenu toggleOn <screen>. The shell's socket answers each call with ok or error.
From the shell to the compositor
The shell sends the methods peek, show-desktop, theme, glass, corners, animations, programs, screens and display. When the line comes up, it sends the settings that the frames use again. If the compositor reloads, the shell tries again each second.
The shell
A Rust program on AntiWebUI. Each surface is a layer-shell surface, except the Control Panel, which is a window. Settings are a reactive value backed by settings.json.
The portal
A D-Bus service. It sends shortcuts with the triggers to bind; the compositor sends back shortcut events with pressed or released.

Run a nested session

tools/dev.sh

The script must run in a graphical session. It links src, assets and shell of ~/.config/shojiwm to the checkout, then starts ShojiWM nested in a window. When the compositor stops, it restores the links of your NixOS configuration with systemd-tmpfiles, if there are any. Run shoji_wm -r from another terminal to reload src. To try a shell that you built with cargo build, run crates/shell/target/debug/shojiwm-shell in the nested session.

Screenshots

tools/screenshots.sh runs the whole desktop with no display: Xvfb holds ShojiWM's nested window, Mesa renders in software, ImageMagick captures, and xdotool drives the keys and the pointer. It needs Nix only.

VariableEffect
THEMEThe theme of the session: aero (default) or kernel.

UNTILStop after the picture of that name, for example desktop.

tools/details.py cuts the enlarged close-ups in assets/site/details/. tools/compare.py puts a reference next to a capture and prints the error per part of the frame; its output stays in /tmp. tools/make-caption-svgs.py draws the caption buttons from the measurements.

Real limits

  • The Alt+Tab panel has square corners. The compositor draws it with <Solid>, which takes a colour and a rectangle and no radius. To round it, a shader must draw the card into a texture.
  • Taskbar thumbnails in the screenshots show the program's icon. The shell asks for a live picture of each window (ext_image_copy_capture or hyprland_toplevel_export). In the headless session that takes the screenshots, no picture arrives, and the card keeps the icon.
  • Aero Peek on one window, from its thumbnail, is not written. The shell knows a window as a foreign-toplevel handle and the compositor as a WaylandWindow; nothing ties the two together yet.
  • Caption buttons under the pointer and pressed are not measured: no reference screenshot shows them. They are drawn from the resting gradient.
  • Not tested on a real GPU in the screenshots. Every capture is drawn by llvmpipe at 1280 × 800 and scale 1, with input from xdotool.
